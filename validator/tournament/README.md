# Validator Tournament

Tournament state machine, participant management, task creation, scoring support, and reporting.

## Contents

- `benchmark_utils.py`: benchmark task copy and benchmark helper logic.
- `brackets.py`: bracket creation and advancement helpers.
- `chaining.py`: read-only helpers for chained quant tasks (`upstream_task_id` = a text seed task of the bound text tournament): the miner rounds R1-R3 and the boss round's six tasks, each compressing the model the text boss trained on one text seed. The shared input is the text boss's output on the seed, so the only candidate is `EMISSION_BURN_HOTKEY` (`shared_input_candidates`, `order_by_upstream_loss`). `chained_input_repo` is the repo our trainer uploaded for a player on the upstream task (the validator-assigned expected repo, never a miner-supplied id), or the merged full model recorded on the seed when the boss uploaded a LoRA adapter (`TournamentSeedTask.merged_output_repo`).
- `constants.py`: tournament schedule, structure, fee, and retry constants.
- `decoder_snapshot.py`: canonical quant `decoder/` snapshot at a pinned commit (`git archive` tar, single-threaded `xz -9` byte count, 1 MiB cap, MinIO upload under `quant-decoders/<commit>/`). Taken once at quant registration, at most `DECODER_SNAPSHOT_CONCURRENCY` at a time; that MinIO tar is the only decoder a freeform decode ever runs, so a training job cannot ship a decoder tailored to its own artifact. An optional `repo_check` runs on the clone before archiving, so registration's build lint shares the clone. The tar is then checked in order: a symlink or hardlink raises `DecoderUnsafeMembers`, since the trainer's extraction rejects one on every freeform task; the xz byte count over the cap raises `DecoderTooLarge`; and `check_decoder_runnable` raises `DecoderNotRunnable` for a tar the trainer's decode would scored-fail on every freeform task: no regular `decoder/decode.py` (`DECODER_ENTRYPOINT`), or members totalling more than `DECODER_MAX_EXTRACTED_BYTES` (64 MiB) extracted. xz rather than raw size, so readable code is not penalised against minified code; single-threaded, because multi-threaded xz changes the block layout and the byte count. `DecoderSnapshot.tree_sha` is `git rev-parse <commit>:decoder`: content only, so it survives the handover push, which squashes history. The tar and xz hashes embed the commit id and time, so they can only be checked against the released `.tar.xz`.
- `registration_lint.py`: quant registration build lint for immutable dependencies. On the registration clone it reads the text Dockerfile the trainer builds (`TEXT_DOCKERFILE_PATHS`) and the `.sh` build scripts its RUNs execute, and reports `unhashed_pip` (an inline `pip install` spec, or a requirements file with an entry lacking `--hash=` or not resolvable into the build context; `#sha256=` URLs, local paths and `uv sync --locked/--frozen` pass), `unpinned_git` (a `git+` ref that is not 40-hex, or a `git clone` without a SHA checkout in the same RUN), `remote_fetch` (curl/wget/`ADD <url>` with no `ADD --checksum`, no `sha256sum -c` in the same RUN and not under `QUANT_TRUSTED_FETCH_URL_PREFIXES`) and `unpinned_base_image` (a FROM/`COPY --from` image neither digest-pinned nor under `QUANT_TRUSTED_BASE_IMAGE_PREFIXES`). `QUANT_REGISTRATION_LINT_ENFORCE` is False: warn-only, a failing entrant is enrolled and its violations logged; when True a failing entrant is excluded. Files over `QUANT_LARGE_FILE_REVIEW_BYTES` are logged for manual review, never rejected. A static heuristic: Python run at build time and runtime fetches stay with manual review.
- `dstack_orchestrator.py`: dstack-backed training orchestration.
- `freeform_release.py`: the public side of freeform decoders. `release_freeform_decoder(tournament_id, hotkey, config, psql_db, allow_boss=False)` publishes the participant's snapshot `.tar.xz` from MinIO to the public HF dataset `<TOURNAMENT_HF_USERNAME>/freeform-releases` under `<tournament_id>/<hotkey>/` together with a `release.json` (`FreeformRelease`), and records `decoder_released_url` and `decoder_released_at`. It is idempotent. A decoder is public only for the tournament's champion: it returns `None` unless `tournament.winner_hotkey == hotkey`, and when the participant has no `backup_repo` (the code push comes first); the burn hotkey is skipped unless `allow_boss` (the one-off release of the reigning champion). A sha256 or byte mismatch against registration refuses the release (alert, nothing published). A failure logs, alerts Discord and is swallowed: it never undoes the code push. `publish_boss_round_decoded_models(tournament_id, config, psql_db)` builds each boss-round freeform submission's bf16 model with `materialise_decoded_model` (sha256-verified shards plus the base config and tokenizer), creates public `<TOURNAMENT_HF_USERNAME>/<expected_repo_name>-decoded`, uploads, and records `task_nodes.decoded_hf_repo`; idempotent, never blocks completion. Validator side only, never on a trainer. See "Freeform publications: background and reconcile" below for how they are run.
- `github_validation.py`: repository/license/commit validation. The licence check reads LICENSE/NOTICE at the entrant's pinned commit (a commit missing from the clone fails it), not the default branch. The obfuscation tool's output is token-sanitised before it is logged.
- `gpu_requirements.py`: tournament GPU requirement calculation. Quant tasks are sized exactly like instruct.
- `models.py`: tournament schemas, training status enums, trainer aggregate views, and response models, including `SeedRole`, `SeedStatus`, `TournamentSeedTask`, `QuantSourceSlot` and `QuantSlotSpec` (the nine places a quant task can fill: R1-R3 and the six boss-round compressions, each with its text seed role and task type), `QuantTaskSource` / `QuantTournamentSource` (the persisted links), `TextRoundSpec` (one entry of `TEXT_ROUND_PLAN`: round number, seed role, model size band, advance count) and `QuantRoundSpec` (one entry of `QUANT_ROUND_PLAN` in `constants.py`: round number, slot, quant task type, text seed role, advance count, optional pinned quant format). The response models carry an additive `quant` / `quant_*` field next to `text` and `image` (next dates, active, details, weights, projections, boss battle).
- `notifications.py`: tournament notification helpers.
- `obfuscation_detection/`: anti-obfuscation binary and wrapper package.
- `orchestrator.py`: trainer assignment and tournament task execution orchestration. `_fetch_tournament_tasks_ready_to_train` feeds three buckets (image, quant, everything else), each while it has fewer than `PENDING_QUEUE_THRESHOLD_PER_TYPE` pending assignments, so neither text nor quant can starve the other. `schedule_tasks_for_training` defers a (task, hotkey) whose bf16 reference row does not exist yet (`_reference_ready`, not a failed attempt): every hotkey waits for the one task-common row stored under hotkey `''`, except that a non-tournament task never waits and, after `QUANT_TASK_COMMON_REFERENCE_MAX_FAILURES` (6) consecutive prepass failures of that row, `reference_gave_up` lets the miners train with no target. `_create_training_request` publishes the stored reference as the miner's `QuantTarget` (`_quant_target_for`; `quant_target_from_reference` turns a stored `QuantSkuReference` into the published reference loss and, for freeform, the knee, cap and penalty curvature) and builds `TrainRequestQuant.calibration` at request time (`_quant_calibration_for`: a fresh presigned URL of the task's `calibration_data`, its `calibration_fingerprint` and `calibration_n_examples`, and the reference hotkey's `quant_calibration_references` row; `None` when absent, which logs an ERROR, alerts once per task via `_alert_missing_calibration`, and still trains). Every tournament quant task carries a set: R1-R3 and the boss-round tasks inherit the calibration set of the text seed task they compress. `_hours_after_prep` is the single post-prep resize: quant tasks are resized from their own prep stats (`quant_hours_after_prep`; unusable stats keep the current hours), the text seeds are capped at `NON_BOSS_INSTRUCT_MAX_TRAINING_HOURS`, and a continuous-SFT task gets the fixed `CONTINUOUS_SFT_TRAINING_HOURS` whatever its stats. `process_awaiting_upstream_tasks` releases a chained quant task held in `AWAITING_UPSTREAM` once the text boss's model on its text seed has landed and its nodes are assigned: `_shared_chained_input` takes the text boss's output on the seed if it is a full model (a hub error other than a missing repo holds the task for a retry; a seed without a usable boss output holds it for the seed's replacement), and that repo becomes the task's `model_id`; `_copy_upstream_data` copies the upstream's prepped split, raw `calibration_data` and dataset type and recomputes the budget (the boss budget for the boss-round tasks, so both players get the same hours); the release records the exact repo in `quant_task_sources.source_model_repo`, falling back to the text task's own base model (`source_is_fallback`) when the text boss produced no usable model: at once for a `failed` text seed (a landed full-model output is still used), once the text tournament is over, and, while it runs, for a succeeded run with an unusable output only after the seed loop has marked the row `trained` or `ready` and the row has been unchanged for `QUANT_SOURCE_FALLBACK_GRACE_SECONDS`. A task held on a `replaced` seed follows the role's successor (live or `failed` row); with none to follow, or a refused re-point, it holds while the text tournament runs and is released like any other once it is over. A task whose `failed` (or abandoned replaced) text task was never prepped has no data to copy and is released on a fresh instruct dataset of its own, which its own prep splits and carves the calibration set from. With no usable shared output every player gets a persisted `quant_failure` and the task is marked FAILURE. Freeform requests carry a `QuantDecodeRequest` for the entrant's registration decoder snapshot. On training success `_record_quant_decode` persists the trainer's decode result to `task_nodes` (scored fail for no snapshot or a `quant_failure`; a `build_warning` is logged and stored in `decoder_build_warning`, never scored); infra errors, a missing result or a snapshot sha/byte mismatch are never scored: the task is held before PREEVALUATION, re-polled each cycle and alerted once per (task, hotkey), as is a re-poll that fails `QUANT_DECODE_REPOLL_FAILURES_BEFORE_ALERT` times in a row. An organic freeform task is never scored for its decode. The trainer request is only ever logged through `loggable_training_request`: the GitHub token and the presigned decoder URL become `***` and every other URL loses its query. Seed priority and hold: `schedule_tasks_for_training` orders its pending rows by `seed_tasks.training_rank` (the rank is the task's, so the challenger's row ties with the boss's row on the same task): the text seeds and every miner-round and other non-seed row rank ahead of the quant boss's six boss-round entries, which rank last. In a cycle where a row ahead of them was left without GPUs, the quant boss's own entries (burn-hotkey rows, `is_boss_entry_row`) are not tried (`miner_row_starved`); a challenger row is never deferred by that skip, a running job is never preempted. A boss-round seed is held in TRAINING until it is attached to the boss round, a non-boss player is assigned and every assigned player's training row is terminal or has a persisted `quant_failure` (`seeds_sql.boss_round_seed_ready_to_finalise`). The hold is on finalisation only: the seed-time evaluation pass seeds each row's evaluation as soon as it trained, so the boss's entries are evaluated and stored at seed time and the boss round evaluates only the challenger (`validator/lifecycle/boss_seed_eval.py` for the seed-time retry, park and alert rules). `process_boss_round_seed_rows` is one more orchestrator cycle: for every attached boss-round seed of an active quant tournament and every attached continuous-SFT seed of an active text tournament it adds training rows for the non-boss players that lack one (never the boss's) and logs `boss entry <task_id> still training` at WARNING while the boss's own row is not terminal; the boss round never waits on it. `process_seed_adapter_merges` is another: when the boss's output on a text seed is a LoRA adapter, a trainer model-prep job (the existing merge) flattens it into a full model whose repo is stored as the seed's `merged_output_repo` and used as the output (`SEED_ADAPTER_MERGE_FAILURES_BEFORE_ALERT` consecutive failures alert; the seed waits, is never redrawn or charged; a failed merge backs off 10 min doubling to 60 min, and after `SEED_ADAPTER_MERGE_MAX_FAILURES` it is parked with one alert until the orchestrator process restarts; a merged repo that exists but is not a full model is deleted on the hub so the next attempt re-uploads it; no merge is dispatched while a trainer cannot be asked about the job, for up to `SEED_ADAPTER_MERGE_UNKNOWN_CYCLES_BEFORE_DISPATCH` cycles; a seed whose output is known to be a full model is not polled again). In `schedule_tasks_for_training` a quant-tournament row that raises is dropped from the scheduling session (it returns with the next fetch) so it cannot hold text and image rows behind it. Own-model start points (`OWN_UPSTREAM_MODEL`, `OWN_R1_MODEL`) are understood by the release, reference and prepass code, but no quant tournament creates such a task.
- `quant_reference.py`: which bf16 model a quant row is normalised by. `quant_reference_model(task, hotkey, db)`: the task's common input (R1-R3 and the boss round: the text boss's output on the text seed the task compresses), or, for a task with an own-model start point, the player's own `starting_model_repo`; `reference_hotkey_for(task, hotkey)` is the key the reference is stored under (`''` task-common).
- `quant_reference_prepass.py`: the quant reference pre-pass (`measure_quant_references_cycle`, run with the orchestrator cycles). Once per task for the hotkey `''` (model `quant_reference_model`, the task's own, augmented when it was; no node or starting model needed; every quant tournament task is task-common) it either copies the previous round's `quant_sku_references` rows (same model and a byte-identical eval set: the fingerprint of this task's downloaded `test_data` is compared locally; the other tasks of its own round also qualify, e.g. the sibling fixed or freeform slot on the same base and data) or measures the bf16 repo in one `run_evaluation_basilica_quant` deployment with `psql_db=None` (so no task_nodes scores, deployment ids or GPU reservations are touched) and stores the row keyed by hotkey and SKU. Bounded by `QUANT_REFERENCE_PREPASS_CONCURRENCY`; a failed measurement is an infra error, retried every cycle and alerted once after `QUANT_REFERENCE_PREPASS_FAILURES_BEFORE_ALERT` consecutive failures. A separate module from `quant_reference.py` because that one is imported by `scoring.tasks` and this one imports evaluation code. A quant task (either track) with `calibration_data` gets a second measurement per reference hotkey, once its scored test reference is stored: the same bf16 repo on the calibration rows (`calibration=True`, run and failure-counted under `(task, hotkey, "calibration")`), stored in `quant_calibration_references` (one row per task and hotkey, not per SKU, never used to score). It is copied from the previous round when the model and `calibration_fingerprint` match. A measurement on other rows than the published set is a failure. `_calibration_reference_ready` (orchestrator) makes a miner's training wait for that row; after `QUANT_CALIBRATION_REFERENCE_MAX_FAILURES` (3) failures in a row the prepass stops waiting, and the miner trains on the rows with `reference` `None`. The failure counter is in memory, so a validator restart starts it again.
- `participants.py`: participant collection and filtering.
- `performance_calculator.py`: tournament performance comparison logic. A boss-round row whose boss or challenger score is non-finite (a scored fail) records no performance difference, and the stored median is always finite.
- `performance_utils.py`: shared performance helpers.
- `repo_diff_report.py`: repository diff report generation.
- `repo_diff_report_config.json`: repo diff report config.
- `repo_uploader.py`: winning repository upload/publishing helpers.
- `reports.py`: tournament report generation.
- `round_results.py`: round winner and elimination logic. Seeded text rounds follow `TEXT_ROUND_PLAN`: each of rounds 1-3 is one instruct seed task played by one group, standings taken from that task with the boss excluded (`_text_seeded_ordered_hotkeys`), top 8, 4 and 1 advance; third place is the next miner after the challenger in round 3's standings (`get_seeded_text_runner_up`). The seeded text boss round is resolved by `_get_seeded_text_boss_round_outcome` on the crown rule in `text_crown.py` (see below): while the big task is not yet in the round the outcome is deferred and the caller adds the big task only if the challenger can still be crowned, otherwise the boss is retained and the big task is never created. Quant rounds follow `QUANT_ROUND_PLAN`: R1 (freeform on the text boss's round-1 model) keeps the top 8, R2 (fixed on its round-2 model) the top 4 and R3 (freeform on its round-3 model) the top 1, each by average rank over every round played so far (`quant_cumulative_winners`); the viability cull (`t3_viability_verdicts`, `t3_viable_winners`) runs after R2. Ranks are taken within the surviving cohort (results of eliminated miners are dropped before ranking; a miner absent from a round or scored-failed ranks last on it), with ties broken by the better rank in the most recent round played (`recent_round_rank`), then summed normalised gap, then a per-round seeded shuffle. Third place for quant is the next miner in the pre-boss group's cumulative standings (`get_quant_pre_boss_runner_up`). A quant boss challenger is crowned when it wins at least 5 of the 6 boss-round tasks (`_quant_boss_round_crowned`): a freeform task is won with at least `QUANT_FREEFORM_BOSS_BYTE_MARGIN` (3%) fewer effective bytes, a fixed task by the paired per-example test plus a scalar loss at least 1% better. A quant boss round holding tasks nobody was assigned to goes back to PENDING for node assignment. Image boss rounds keep their own rule (all but one of 6).
- `runner.py`: tournament loop runner.
- `seed_tasks.py`: seed tasks, everything the boss trains upfront when a tournament's first round is created, with its pinned repo and commit (`TournamentSeedTask`, table `tournament_seed_tasks`, SQL in `validator/db/sql/tournament_seeds.py`). A text tournament has four seeds (`TEXT_SEED_CREATION_ORDER`, trained by the text boss at tournament start): `text_r1` (instruct, 1-4B), `text_r2` (instruct, 1-4B), `text_r3` (instruct, 4-8B) and `text_continuous` (the continuous-SFT chunk task of the boss round). Rounds 1-3 attach their seed as the round's task; the continuous seed is attached by the boss round. A quant tournament has six seeds (`SEED_CREATION_ORDER`, trained by the quant boss): `boss_r2_freeform`, `boss_r2_fixed`, `boss_r3_freeform`, `boss_r3_fixed`, `boss_continuous_freeform`, `boss_continuous_fixed`, the freeform and the fixed compression of the text boss's round-2, round-3 and continuous models. Each is a new quant task of its own on a seed of the bound text tournament (`quant_sources.py`), held until the text boss's model has landed; the fixed format of a boss-round task is drawn from `QUANT_BOSS_ROUND_FIXED_FORMATS` (2-bit or 3-bit), seeded by tournament and role so a restart or replacement redraws the same one (`_boss_fixed_format`). The roles `input_small`, `input_large`, `boss_instruct`, `boss_chained_freeform`, `boss_chained_fixed` and `boss_continuous_instruct` are not created; they stay in the enum and the DB check so existing rows load. `create_seed_tasks` (idempotent per role) draws each task, records the seed row before anything else, and assigns the boss node (`EMISSION_BURN_HOTKEY`) with the expected repo `tournament-<tid>-<task_id>-<hotkey8>`; the boss participant row's 40-hex commit (fetched at tournament creation, else pinned from the repo HEAD) is the code every seed trains. `process_tournament_seed_tasks` moves a seed `training` -> `trained` (attached seeds, held for their round) -> `ready`, and replaces a failed one (`replace_seed`: prep failure, the boss's run failed, the upload is not a full model, or a text seed scored no fine-tune) with a fresh draw as attempt+1, re-pointing dependents (held quant tasks via `repoint_task_onto_seed`), up to `SEED_MAX_REPLACEMENTS` real failures; then the row is `failed` and Discord is alerted once per tournament and role (`_alert_role_out_of_replacements`). A `failed` text or quant boss-round role never halts or blocks the tournament: only an input-seed role (`input_small`, `input_large`, `boss_instruct`, ...) halts it (`seed_halt_reason`). A failed text round role (`text_r1`-`text_r3`) leaves its round to draw one ordinary instruct task of its own (`task_creator.draw_text_round_task`, no seed row and no boss assignment, so the boss has no result on it and the challenger takes it with a valid score, `text_crown.text_head_to_head`); a post-attach prep failure of such a seed falls through to `replace_tournament_task`, which redraws with the same helper and does not copy the boss's node. A failed `text_continuous` makes the boss round draw its own continuous task on the single lineage (`create_continuous_sft_task`) and register it under the pair; both players train it. While a role's latest row is `replaced` (a replacement pending) the round still waits (`MissingBossRoundSeeds`). Quant tasks on a failed text role fall back to the text task's base model. A boss upload that is a LoRA adapter is not a failure: the seed waits for its merge into a full model (`boss_output_awaits_merge`, `process_seed_adapter_merges` in `orchestrator.py`) and is not redrawn. A prep-stage dataset rejection of a dataset-drawn role (the text instruct seeds ending `PREP_TASK_FAILURE`; `is_prep_rejection`) is not a real failure: it is stored `prep_rejected` and redrawn without consuming `SEED_MAX_REPLACEMENTS`, skipping every dataset already prep-rejected in the tournament (`_excluded_datasets`, `_without_datasets`); the `SEED_MAX_PREP_REJECTIONS`-th rejection of one role fails the row and alerts once (`alert_seed_issue`; a text role does not halt). A prep rejection of a compression (same upstream data, so a redraw cannot help) counts against `SEED_MAX_REPLACEMENTS`. `seeds_sql.boss_round_seed_ready_to_finalise` (in `validator/db/sql/tournament_seeds.py`, so lifecycle can use it without importing the tournament package) is the hold applied on every finalising path: a seed is finalised (ranked and closed) only once its round has attached it and every assigned player has finished; the boss's own entry is evaluated as soon as it has trained, so its scores are stored up front. `training_rank` / `row_training_rank` / `training_ranks` give the trainer priority, by the task's rank for both players; the quant boss's own entries yield in a cycle where an earlier row is short of GPUs. A seed is never replaced once it was attached (`attached_round_id`, written when a round attaches it) except for a prep failure (`_replacement_blocked`; `MissingBossRoundSeeds` from the attach alerts once via `_alert_missing_boss_round_seeds`): a post-attach prep failure (`seeds_sql.boss_side_seed_failure`) completes the slot without `replace_tournament_task` and the challenger gets the slot (a boss-side failure); a role with no live row (a failed re-draw) is re-created by `process_tournament_seed_tasks` until a round attached one of its seeds (capped by `SEED_MAX_REPLACEMENTS`); draw failures and refused replacements alert once per tournament and role (`alert_seed_issue`).
- `quant_sources.py`: the link between a quant tournament and the text tournament its tasks come from. `bind_quant_source_tournament` binds a quant tournament to the most recent text tournament that has its four text roles and feeds no quant tournament yet (stored in `quant_tournament_sources`): active text tournaments first (each role live or `failed`; a role whose latest row is `replaced` makes it wait for the replacement), then text tournaments completed within `QUANT_SOURCE_COMPLETED_WINDOW_SECONDS` (7 days; their seed state is final, so a row of any status per role is enough). A text tournament with no seed rows is never bound. Until there is one the quant tournament waits, nothing is created and nothing is halted; the wait is logged once per process and one Discord alert goes out after `QUANT_SOURCE_WAIT_ALERT_SECONDS` (2 h, measured from when this process first saw it waiting, since the tournaments table keeps no activation time). `slot_text_seed` resolves the text seed row of a `QuantSourceSlot` (`final_text_seed`): the role's live row, else its latest row when that is final (`failed`, or the text tournament is over), None only while a replacement is pending in a running text tournament, so a failed role never stops a quant task from being created (it is chained on the failed seed's task and takes the fallback); `record_new_quant_task` stores a new quant task's source row in `quant_task_sources` (quant tournament and slot, text tournament, text seed role and task, model repo, fallback and superseded flags) so a slot never has two live tasks and a quant task never exists without its link. SQL in `validator/db/sql/quant_sources.py`.
- `task_creator.py`: tournament task creation. Seeded text rounds 1-3 attach the round's seed task (`_attach_text_round_seed`: no task is drawn, the seed gets a `tournament_tasks` row under the round's group and is marked attached, which releases its finalisation; round 1 attaches at once, so miners train it in parallel with the boss). The seeded text boss round (`_create_seeded_text_boss_round_tasks`) attaches the continuous seed and creates one GRPO and one DPO task (`TEXT_BOSS_ROUND_STAGE_ONE_TASK_TYPES`); the big task (`create_seeded_text_big_task`, an instruct task on a 30-72B model from the `BOSS_ROUND_LARGE_INSTRUCT_*` pool) is created only after stage one is scored and only if the challenger can still be crowned. Quant miner rounds are `QUANT_ROUND_PLAN` (`quant_round_spec`): `_create_seed_input_round_task` creates the round's one quant task, chained on the live text seed of the round's text role (`text_r1` for R1 freeform, `text_r2` for R2 fixed, `text_r3` for R3 freeform) of the bound text tournament, held in `AWAITING_UPSTREAM`; a fixed round plays the format pinned in its `QuantRoundSpec` (R2: `W2A16-asym-g64`), else one drawn from a round-seeded rng; creation is idempotent and a replacement is an identical held copy. No quant round has an instruct task and no miner trains an instruct model; the seed tasks' own creation is in `seed_tasks.py`. The quant boss round is exactly `FINAL_ROUND_QUANT_TASK_DISTRIBUTION` (6 tasks: three freeform, three fixed). `_create_quant_boss_round_tasks` attaches the six upfront boss-round seeds (`_attach_boss_round_seeds`: inserts their `tournament_tasks` rows under the round's pair, idempotent, raises `MissingBossRoundSeeds` while a role has no live seed so the round stays PENDING) and draws no new task. `create_quant_tournament_tasks` is the quant dispatcher (a group round creates the round's quant task, the final round attaches the boss-round seeds); `create_text_tournament_tasks` and image creation dispatch the seeded and unseeded paths. Replacing a text seed task re-points its chained quant dependents.
- `task_results.py`: task result loading for rankings.
- `text_crown.py`: the crown rule of a seeded text tournament, pure functions and models only (`text_head_to_head`, `text_crown_verdict`). The challenger and the boss are compared on 7 tasks (rounds 1-3 and the 4 boss-round tasks). A task is a win when the challenger beats the boss by at least `TEXT_CROWN_WIN_MARGIN` (1%) of the boss's score magnitude; any other task is a non-win with a deficit (how far the challenger trails, relative to the boss's score; 0 when level or ahead by less than the margin). The challenger is crowned with at most `TEXT_CROWN_MAX_NON_WINS` (2) non-wins, no deficit above `TEXT_CROWN_MAX_DEFICIT` (0.25%) and, with two non-wins, one deficit at most `TEXT_CROWN_SECOND_NON_WIN_MAX_DEFICIT` (0.1%). No valid challenger result is a non-win with an unbounded deficit; a boss with no valid result while the challenger has one is a win. `crowned_if_complete` counts every undecided task as a win, which is the early-stop test after round 3 and after the first three boss-round tasks.
- `thresholds.py`: boss/champion threshold helpers, including `sku_aligned_losses`: a quant per-example vector from another SKU expressed on the anchor's SKU (`x_i * ref_i(anchor) / ref_i(own)`) before any paired comparison.
- `tournament_manager.py`: high-level tournament lifecycle manager. `process_tournament_scheduling` checks text, quant and image every cycle (no feature flag); `check_and_start_tournament` creates a type's next tournament in its slot (quant Monday 09:00, text 11:00, image 13:00 UTC; `_get_tournament_schedule`) once the previous one of that type completed, and the first tournament of a type starts at once. A quant tournament that has no bound text tournament yet waits (see `quant_sources.py`). Types are independent: a tournament blocks only its own type. Participation fees are per type (`TOURNAMENT_TEXT/QUANT/IMAGE_PARTICIPATION_FEE_RAO`). A new tournament's boss is the latest completed tournament of its own type, or, for quant with no completed quant tournament, of the type in `BOSS_SEED_TOURNAMENT_TYPE` (text); `participants.get_latest_tournament_winner_participant`. `create_first_round_for_active_tournament` first calls `create_seed_tasks` for a text tournament (its four seeds) and for a quant tournament once it is bound to a text tournament (its six seeds); all must exist (a role whose latest row is `failed` counts as present), else it logs and retries; the active-tournament loop runs `process_tournament_seed_tasks` each pass and does not advance a tournament while `seed_halt_reason` is set (only an input-seed role sets it; a failed text or quant role never does). Text and quant rounds 1-3 are each a single group (the next round never contains the burn hotkey); the lone survivor is paired with the burn hotkey for the boss round. Text third place is the next miner after the challenger in round 3's standings; quant third place comes from the pre-boss round's standings (R3, or R2 when R3 is skipped), falling back to the knockout loser; image third place is the knockout loser. Quant registration excludes an entrant whose pinned commit has no snapshot-able `decoder/` (missing, over the cap, symlinks/hardlinks inside, not runnable by the trainer, or clone/xz timeout) and stores the snapshot on its participant row; the build lint (`registration_lint.py`) runs on the same clone and, while it is warn-only, only logs a failing entrant's violations; once enforced it excludes the entrant too. Text and image entrants need no decoder. The boss is snapshotted too (never linted), and without a decoder it keeps empty fields and scored-fails every freeform task. The pending and active loops handle each tournament in its own `try`, so one raising tournament cannot stop the others. `populate_tournament_participants` is a single pass: a tournament below `MIN_MINERS_FOR_TOURN` returns 0, stays pending, is alerted once and re-pings miners every `TOURNAMENT_PARTICIPANT_RETRY_INTERVAL_SECONDS` (30 min), without blocking the other pending tournaments. The quant boss's decoder snapshot never raises out of `create_basic_tournament`; while the tournament is pending `_repair_quant_boss_participant` recreates a missing boss row and retries a transiently failed snapshot (`BOSS_DECODER_REPAIR_COOLDOWN_SECONDS`), a boss with no usable decoder is alerted and not retried. A boss-round seed that failed prep is never replaced: the challenger takes the slot only if it has a usable run there, otherwise the boss keeps it. The manager checks the crown rule (`text_crown_verdict`) after round 3 and after stage one of the boss round, and ends the tournament early, boss retained, once a crown is out of reach.
- `transfer_monitoring.py`: tournament fee transfer monitoring.
- `utils.py`: remaining tournament utility helpers; prefer narrower modules for new code.

## Text tournament flow

1. Activation: `create_seed_tasks` creates the four text seeds (`text_r1`, `text_r2`, `text_r3`, `text_continuous`); the boss trains them at tournament start with its pinned code. Round 1 attaches `text_r1` at once, so miners train it in parallel with the boss.
2. Rounds 1-3 (`TEXT_ROUND_PLAN`): each attaches its seed task, one group, standings with the boss excluded; top 8, 4 and 1 advance.
3. Boss round, stage one: the continuous seed is attached and one GRPO and one DPO task are created; the challenger trains the continuous task, both players train GRPO and DPO. Stage two: the big task, only if the challenger can still be crowned.
4. Crown rule: `text_crown.py`, checked after round 3 and after stage one, and again once the big task is scored.

## Quant tournament flow

1. Binding: the quant tournament is bound to one text tournament that has its four text seeds (live or `failed`) and feeds no other quant tournament: an active one, else one completed within the last 7 days (`quant_tournament_sources`). Until then it waits, with an alert after 2 hours. A `failed` text role never stalls the quant tournament: its slots take the text task's base model as the fallback.
2. Activation: `create_seed_tasks` creates the six quant boss-round seeds, each a held quant task on a text seed; the quant boss trains each as soon as the text boss's model has landed. Round 1 is created once all six exist.
3. R1 (freeform on the text boss's round-1 model, all entrants to 8), R2 (fixed on its round-2 model, to 4, then the viability cull), R3 (freeform on its round-3 model, to 1): `QUANT_ROUND_PLAN`. Each is one quant task chained on a text seed, released when the text boss's model has landed. Cuts use average rank over every round played within the surviving cohort, ties by the most recent round.
4. Boss round: the six boss-round seeds are attached; only the challenger gets new training rows (`process_boss_round_seed_rows`), compressing the same models the boss did. The challenger must win 5 of the 6 tasks: freeform on effective bytes (3% margin), fixed on the paired test plus a 1% scalar improvement, as described in `round_results.py` and `thresholds.py`; the crown rule is `_quant_boss_round_crowned`.
5. Seeds' data is hidden on public and auditing endpoints until the last round that uses them completes (`get_hidden_seed_task_ids`). Text seeds follow their quant tournament instead: a text seed is hidden while a live quant task source of a running quant tournament names it, and a quant task chained on it until its own quant tournament is completed or cancelled.

Migrations: `validator/db/migrations/20261109120000_tournament_seed_tasks.sql`, `20261112120000_tournament_seed_merged_output_repo.sql` (`merged_output_repo`), `20261113120000_continuous_sft_50k_chunks.sql` (continuous-SFT chunk scheme), `20261113130000_text_seed_roles.sql` (text seed roles and the quant boss-round roles) and `20261113140000_quant_task_sources.sql` (`quant_tournament_sources`, `quant_task_sources`).

## Design notes

- **Boss-trained inputs are fair.** The quant boss does not play R1-R3, and the models the quant tournament compresses
  are trained by the text boss on the validator's draw of base model and dataset. The text boss's code is public from
  its handover, so every miner can read what trained the input. The boss-round models are the text boss's round-2,
  round-3 and continuous models; the quant challenger trains no instruct model, and compresses the same models the quant
  boss did. The quant boss's six compression entries are public on HF before the challenger trains; training containers
  have no network and pinned code, so this only allows offline study.
- **Hold rule.** A seed is a TRAINING task whose only row is the boss's until its round attaches it and adds the
  other players. It is ranked and closed once, when `seeds_sql.boss_round_seed_ready_to_finalise` holds (attached,
  a non-boss player assigned, every assigned row terminal or with a persisted `quant_failure`); until then
  `lifecycle.tasks._finalize_task_status_from_evaluations` returns early and `_move_completed_tasks_to_preevaluation`
  skips it. The dstack path (which sets PREEVALUATION itself) handles only priority-1 organic rows, so no seed takes it.
  Chained release does not wait on this hold: it keys on the text boss's model on the text seed having landed as a usable
  full model, so the quant boss's six compressions run on spare GPUs as soon as each source model is trained. R1-R3 wait
  for their text seed's model the same way.
- **Seed-time boss evaluation.** The boss's row is evaluated the moment it is SUCCESS (`orchestrator.seed_tournament_evaluations_from_training`,
  the ordinary per-(task, hotkey) path), and the round evaluates only the challenger. Everything ranking reads is stored
  by the evaluation (`task_nodes`: test loss, per-example losses, eval-set fingerprint, `eval_gpu`, bytes,
  `quant_failure`; `quant_sku_references`), and penalty, cap verdict and `adjusted_loss` are derived at ranking from
  those and the task's pinned policy, so the verdicts do not depend on when the boss was scored. Error handling is in
  `validator/lifecycle/boss_seed_eval.py`; a validator restart forgets retry counts (at worst a fresh retry budget,
  never a second score).

## Decoder columns and public participants

`TournamentParticipant` (`validator/tournament/models.py`) carries the registered decoder snapshot. Set at registration by
`_with_decoder_snapshot` (entrants and boss), persisted with the participant row; migration
`validator/db/migrations/20261108120000_quant_freeform_exposure.sql`:

| Field | Meaning | Public |
| --- | --- | --- |
| `decoder_object_name` | MinIO key of the snapshot `.tar.xz` | never |
| `decoder_xz_bytes`, `decoder_sha256` | counted size and sha256 of the `.tar.xz` | yes, via the scorecard |
| `decoder_tar_sha256` | sha256 of the uncompressed canonical tar | yes, via the scorecard |
| `decoder_tree_sha` | git tree id of `decoder/` | yes, via the scorecard and `release.json` |
| `decoder_xz_version` | `xz --version` line that compressed the snapshot | yes, via the scorecard |
| `decoder_released_url`, `decoder_released_at` | the public release, set by `release_freeform_decoder` | yes, via the scorecard after handover |

`_public_participants` (`validator/endpoints/tournament_analytics.py`) is applied to the participant list before any
HTTP or Redis response. It sets `github_token` and `decoder_object_name` to null and nothing else. The training repo URL
stays, because results are labelled by it; the snapshot hashes are public. Internal DB and orchestration code keeps the
full model.

## Freeform publications: background and reconcile

Neither publication runs inline. `upload_participant_repository` (quant only, after a successful push) calls
`schedule_freeform_release` and the two completion paths call `schedule_boss_round_publication`; each is an
`asyncio.create_task` kept in a module-level set until done, so the code push and the serial active-tournament loop never
wait on GBs of HF uploads. All publication work (background tasks and reconcile) runs under one lock per event loop, taken
per item, so a reconcile pass cannot publish what a background task is part-way through. `wait_for_background_publications`
joins them (tests, CLI).

A scheduled task is lost with the process, and `advance_tournament` returns early once `winner_hotkey` is set, so nothing
else retries it. `reconcile_freeform_publications(config, psql_db, apply=True)` re-derives the unpublished work from the
database (quant tournaments with a `winner_hotkey`, not COMPLETED, since tournaments stay ACTIVE until flipped by hand):
winners' decoders with a snapshot, a `backup_repo` and no `decoder_released_at`; winners blocked for lack of a
`backup_repo` (reported and warned about, the GitHub push is not retried); and tournaments with a final-round freeform
`task_nodes` row that has `decoded_files` and no `decoded_hf_repo`. It returns a `FreeformReconcileReport`; `apply=False`
only reads. `process_freeform_publications` runs it at validator start and then every
`FREEFORM_PUBLICATION_RECONCILE_INTERVAL` (3600 s, slow because each failing item re-downloads GBs and re-alerts).
The first pass publishes any historical winner that has a snapshot row and no release.

By hand, `python -m ops.tools.quant.reconcile_freeform_publications` (read-only by default; `--apply`, `--release`,
`--publish-decoded`, `--json`; see `ops/tools/README.md`).

`_public_participants` stripping `decoder_object_name` is cosmetic, not a security property: the object name is
`quant-decoders/<training_commit_hash>/<decoder_sha256>.tar.xz` and both components stay in the same response
(`training_commit_hash`, `decoder_sha256`). The real control is that the bucket is private and every MinIO link is
presigned.
